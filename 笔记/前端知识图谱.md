## 基础知识

### 浏览器地址栏输入地址到显示页面的步骤
1. 地址栏输入资源地址
2. 浏览器查看缓存，如果资源在缓存中并且新鲜，跳转到解码步骤
    + 如果资源未缓存，发起新请求
    + 已缓存，检查是够新鲜，新鲜则提供给浏览器，否则与服务器进行验证
    + 检查新鲜通常由Expires和Cache-Control进行控制：
        - HTTP1.0提供Expires，值为一个绝对时间表示环讯新鲜日期
        - HTTP1.1提供了Cache-Control：max-age，值为以秒为单位的最大新鲜时间
    + 与服务器进行验证新鲜由Etag HTTP头进行控制
3. 浏览器解析URL获取协议、主机、端口、路径
4. 浏览器封装HTTP请求(GET)报文
5. 浏览器获取主机IP地址
    + 查看浏览器缓存
    + 本机缓存
    + hosts文件
    + 路由器缓存
    + ISP DNS缓存
    + DNS递归查询
6. 打开一个socket与目标IP地址、端口建立TCP链接，进行三次握手：
    + 客户端发送一个TCP的SYN=1，SEQ=X的包到服务器
    + 服务器响应SYN=1，ACK=X+1，SEQ=Y的响应包
    + 客户端发送ACK=Y+1，SEQ=Z
7. TCP建立之后发送HTTP请求
8. 服务器接受请求并解析，将请求转发到服务程序，如虚拟主机使用HTTP Host头部判断请求的服务程序
9. 服务器检查HTTP请求头是否包含缓存验证信息，如果验证缓存新鲜，则返回304状态码
10. 处理程序读取完整请求并准备HTTP响应，可能需要查询数据库等操作
11. 服务器将响应报文通过TCP链接发送回服务器
12. 浏览器收HTTP响应，然后根据情况选择关闭TCP链接还是保留重用，关闭TCP链接的四次握手如下：
    + 主动方发送FIN=1，ACK=Z，SEQ=X的报文
    + 被动方发送ACK=X+1，SEQ=Z的报文
    + 被动方发送DIN=1，ACK=X，SEQ=Y的报文
    + 主动方发送ACK=Y，SEQ=X的报文
13. 浏览器检查响应状态码：1xx,3xx,4xx,5xx与2xx的情况处理不同
14. 如果资源可缓存，进行缓存
15. 对响应进行解码（如资源进行了gzip压缩）
16. 根据资源类型决定如何处理（如资源为HTML）
17. 解析HTML文档，生成DOM树，下载资源构造CSSOM树，执行JS脚本，无严格先后顺序
18. 构建DOM树：
    + Tokening：根据HTML规范将字符流解析为标记
    + Lexing：词法分析将标记转换为对象并定义属性和规则
    + DOM construction：根据HTML标记关系将对象组成DOM树
19. 解析过程中遇到图片、样式表、JS文件则启动下载
20. 构建CSSOM树：
    + Tokening：字符流解析为标记
    + Lexing：根据标记创建节点
    + CSSOM：节点创建CSSOM树
21. 根据DOM树和CSSOM树构建渲染树
    + 从DOM树的根节点遍历所有可见节点，不可见节点：1）script，meta本身不可见的标签 2）被css隐藏的节点，如display: none;
    + 对每一个可见节点，找到恰当的CSSOM规则并应用
    + 发布可见节点的内容和计算样式
22. JS解析如下
    + 浏览器创建Document对象并解析HTML，将解析到的元素和文本节点添加到文档中，此时document.readystate为loading
    + HTML解析器遇到没有async和defer的script时，添加到文档中，然后开始解析执行脚本，此过程将导致解析器暂停
    + 浏览器遇到async属性的脚本时，下载与浏览器解析器并行运行，下载完之后立即执行,不能调用document.write()
    + 浏览器遇到defer属性的脚本时，下载与浏览器解析器并行运行，下载完之后会延迟到脚本能访问完整文档树时执行（即：DOMCotentLoaded后执行）,不能调用document.write()
    + 浏览器在Document对象上出发DOMContentLoaded事件
    + 此时文档解析完成，但浏览器可能还在等待图片等内容加载，等这些内容完成载入并且所有脚本完成载入和执行，document.readyState变为complete,window触发onload事件
23. 显示页面（HTML解析过程中会逐步显示页面）

### HTTP协议
#### HTTP协议概述
是一种被设计成用于获取HTML文件等网络资源的通讯协议。

#### HTTP协议的组成
##### 请求的组成
```
GET / HTTP/1.1
Host: google.com
Accept-Language: zh-cn
Connection：Keep-alive
Cache-Control: max-age=0
Accept: text/html
User-Agent: Mozilla/5.0
Referer: 
Accept-Encoding: gzip,deflate
Cookie: 
If-None-Match: "zfffd-fshfk"
If-Modified-Since: Wed，01 Sep 2004 13:24:52 GMT

name=jj&pwd=fej
```
- 请求行：Http请求方法，请求路径，HTTP协议版本，CRLF
- 请求头部
- 请求体

##### 响应的组成
```
HTTP/1.1 200 OK
Date: 
Server: 
Last-Modified: 
ETag:
Content-Length:
Xontent-Type: 

{name: "",age: ""}
```
- 状态行:协议版本号 状态码 状态信息
- HTTP响应头
- CRLF
- 消息实体

#### HTTP协议的基本性质
1. 简单的
2. 可扩展的
3. 无状态，有会话

#### HTTP请求方法
1. GET：请求服务器发送某个资源
2. HEAD：与GET类似，但只返回头部不返回主体
3. PUT：请求服务器使用请求的主体部分新建一个文档，若此文档已存在则用此次请求的主体替代它
4. POST：用于向服务器输入数据
5. TRACE：用于诊断，验证请求是否如愿穿过了请求/响应链
6. OPTIONS：请求服务器告知器支持的各种功能
7. DELETE：请求服务器删除指定的资源

#### HTTP状态码及其含义
+ 1XX：信息状态码
    * 100 Continue：客服端应当继续发送请求。此临时响应用于通知客户端他的部分请求已被服务器接收，切任未被拒绝。客户端应当继续发送请求的剩余部分，如果请求已完成，忽略这个请求。服务器必须在请求完成后向客户端发送一个最终响应。
    * 101 Switching Protocols：服务器已经理解了客户端的请求，并将通过Upgrade消息头通知客户端采用不同的协议完成这个请求。在发送完响应的最后的空行后，服务器将切换到Upgrade消息头中定义的那些协议
+  2XX：成功状态码
    *  200 OK：请求成功，请求所期望的响应头和数据体将随此响应返回
    *  201 Created：
    *  202 Accepted：
    *  203 Non-Authoritative Information：
    *  204 No Content：
    *  205 Reset Content：
    *  206 Partial Content：
+ 3XX：重定向
    * 300 Multiple Choices：
    * 301 Moved Permanently：
    * 302 Found：
    * 303 See Other：
    * 304 Not Modified：
    * 305 Use Proxy：
    * 306 unused：

    * 400 Bad Request:

    * 404 Not Found:

    * 409 Conflict:

### 网站性能优化
+ content方面
    * 减少HTTP请求：合并文件、CSS精灵、inline image
    * 减少DNS查询：DNS查询完成完成之前，浏览器不能从这个主机少下载任何东西。方法：DNS缓存，资源分布到恰当数量的主机名，平衡并行下载和DNS查询
    * 避免重定向：多余的中间访问
    * 使Ajax可缓存
    * 非必须组件延迟加载
    * 未来所需组件预加载
    * 减少DOM元素数量
    * 将资源放到不同域下：浏览器对同时从一个域下载资源的数量有限制，增加域可提高并行下载数量
    * 减少iframe
    * 尽量不要404
+ Server方面
    * 使用CDN
    * 添加Expires和Cache-Control响应头
    * 进行gzip压缩
    * 配置ETag
    * Ajax使用GET进行请求（Yahoo有推荐这么做）
    * 避免空src的img标签
    * Flush Buffer Early
+ Cookie
    * 减少Cookie大小
    * 引入资源的域名不要包含Cookie
+ CSS方面
    * 将样式表放到页面头部
    * 不实用CSS表达式
    * 不实用@import
    * 不实用IE filter
    * 压缩代码
+ JavaScript方面
    * 将脚本放到页面底部
    * 将JavaScript和CSS作为文件从外部引入（少量的代码直接放在页面中）
    * 压缩代码
    * 删除不需要的脚本
    * 减少DOM访问
    * 合理设计事件监听
+ 图片方面
    * 优化图片，压缩图片
    * 优化CSS精灵
    * 不要在HTML中拉伸图片
    * 保证favicon小并且可缓存
+ 移动方面
    * 保证组件足够小，25kb
    * 将组件到打包成多份文档

### SEO
+ 合理的title,description,keywords
    * title: 强调重点，不同页面title要有所不同
    * description: 对页面内容高度概括，长度合适，不要堆砌关键字，不同页面有所不同
    * keywords: 列举出重要的关键字
+ 语义化的HTML代码，符合W3C规范：让搜索引擎容易理解网页
+ 重要HTML代码放在最前面：搜索引擎抓取HTML顺序从上到下，并且对抓取长度有限制，保证重要内容被抓取
+ 重要内容不要使用JS输出：爬虫不会执行JS获取内容
+ 少用iframe：搜索引擎不会抓取iframe中的内容
+ 非装饰性img必须加上alt
+ 提高网站速度：网站速度是搜索引擎排序的重要指标
+ 扁平化的HTML结构：保证HTML结构尽量简单
+ 对网站首页中的链接不要过少或过多：首页权重大

### 渐进式增强
进行web设计时强调可访问性、语义化HTML标签、外部样式表和脚本。保证所有人能访问最基本内容和功能同时为高级浏览器和高带宽的用户提供更好的用户体验。核心原则：
+ 所有浏览器都能访问基本内容
+ 所有浏览器都能使用基本功能
+ 所有内容都包含在语义化标签中
+ 通过外部CSS提供增加的布局
+ 通过非侵入式、外部JS提供增加功能

## HTML
### DOCTYPE作用
1. <!DOCTYPE> 声明必须位于文档头部，在html标签之前，在HTML5中不区分大小写
2. 不是一个HTML标签，适用于告诉浏览器当前HTML版本的指令
3. 现代浏览器通过检查DOCTYPE决定HTML布局引擎是使用兼容模式还是标准模式来对文档进行渲染
4. 在HTML4.01中doctype声明指向一个DTD，由于HTML4.01基于SGML，所以DTD指定了标记规则以保证浏览器正确渲染内容
5. HTML5不基于SGML，所以不用DTD

### BFC
(Block Formating Context)块级格式化上下文。
**创建规则：**
1. 根元素
2. 浮动元素
3. 绝对定位元素
4. display取值为：inline-block,table-cell,table-caption,flex,inline-flex
5. overflow不是visible
**作用：**
1. 可以包含浮动元素
2. 不被浮动元素覆盖
3. 组织父子元素margin重叠

### FOUC
(Flash Of Unstyled Content): 加载用户自定义样式之前，浏览器以默认样式渲染内容。用户样式加载之后再重新显示文档，造成页面闪动。解决办法：将样式表添加到head中
