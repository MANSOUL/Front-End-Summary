## 小程序

### 小程序的发展背景

JS-SDK解决了网页能力不足，但并没有解决体验不良的问题，需要一个更强大的系统

1、快速加载
2、接近原生的体验
3、更强大的能力
4、开发方便

于是小程序诞生了；

### 小程序原理

浏览器中渲染和脚本执行是互斥的；
而小程序中逻辑层和视图层是分开的，分为两个线程，逻辑层通过setData更改数据，将数据传给视图层，驱动视图层更新；

### 小程序生命周期

#### 应用生命周期

- onLaunch 小程序初始化完成时触发
- onShow 启动/进入前台时触发
- onHide 隐藏时触发
- onError 脚本错误/API调用报错时错误触发
- onPageNotFound 要打开的页面不存在时触发
- onUnhandledRejection 有未处理的Promise拒绝时触发
- onThemeChange 切换主题时触发

#### 页面生命周期

- onLoad(query) 监听页面加载，获取query参数
- onShow 监听页面显示
- onReady 页面初次渲染完成
- onHide 监听页面隐藏
- onUnload 监听页面卸载

#### 组件生命周期

- created 刚创建时触发
- attached 添加到节点树时触发
- ready 准备就绪时触发（表示组件在渲染线程中渲染完毕），不推荐使用
- moved 在节点树中移动时触发
- beforeDetach 将被移除时触发
- detached 被移除后触发
- error 组件内生命周期发生错误时触发


### 小程序路由跳转

- wx.navigateTo 保留当前页面，跳转到下一个页面
- wx.redirectTo 关闭当前页面，跳转到下一个页面
- wx.switchTab 跳转到tabBar页面，并关闭其他非tabBar页面
- wx.navigateBack 返回上一个页面
- wx.reLaunch 关闭所有页面，打开到应用的某个页面


### 性能优化

#### 加载时
1、开启代码压缩
2、压缩图片资源、包内只放必要的icon图标资源，其余的媒体资源通过网络请求获取
3、使用分包
4、预加载分包

#### 渲染
1、网络请求提前到onLoad中
2、减少非必要网络请求，可使用本地缓存
3、减少set次数Data，多次setData合并
4、非页面渲染数据不放在data中
5、避免shadow树过大，可适当划分组件，减少当前shadow树的节点数量：因为在执行虚拟树更新时，需要对整个shadow树进行深度优先遍历；
6、页面中频繁更新的部分封装成独立组件
7、减少setData更新的数据量：减少逻辑和视图层的通信量
8、非必要不监听scroll：只要监听，就认为需要scroll事件，每次事件都会从视图层发送到逻辑层
9、CSS transform、渐变等等


### 登录流程

1、通过wx.login() 获取 code
2、客户端调用开发者服务器登录接口，将code传递给服务器，服务器调用 code2session 接口获取（带上appid、appsecret、code）openid，unionid
3、服务器自定义登录状态
4、返回登录信息

### 支付流程
用户登录后：
1、客户端将商品信息openid传给服务端
2、服务端生成平台订单
3、服务端请求微信下单接口，创建预付单，成功后微信服务端返回给预付单id
4、服务端根据相应规则，生成带签名的支付信息，并返回给客户端（id、时间戳、签名等等）；
5、客户端获取支付信息后调用wx.requestPayment进行支付
6、微信服务进行鉴权返回支付结果给前端和后端
7、客户端进行结果处理
