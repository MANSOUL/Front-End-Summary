### 闭包

闭包指的是函数内部变量的可访问性，函数外部无法访问到函数内部的变量。

而其实现原理则需要牵扯到执行上下文的概念。

#### 什么是执行上下文？

执行上下文是对javascript代码执行环境的抽象，可以理解为js代码执行在执行上下文中。

分为：
- 全局执行上下文
- 函数执行上下文
- eval函数执行上下文

#### 执行上下文的生命周期

包含三个阶段：创建阶段、执行阶段、回收阶段

**创建阶段**：

创建阶段即当函数被调用时做了三件事：

- 确实 `this` 的值，成为 this Binding
- 创建词法环境`LexicalEnvironment`组件
- 创建变量环境`VariableEnvironment`组件

词法环境包含内部包含两个组件：环境记录器和对外部环境的引用（意味着可以访问其父级词法环境，也就是作用域）；
变量环境同样是一个词法环境，不同处在于它的环境记录器用来存储由var声明的变量，而前者存储let和const。

**通过伪代码理解**

#### 闭包

闭包的形成：函数中的所定义的变量无法被函数在外部访问。因此如果要访问函数中的变量，可以在函数内部再定义一个内部函数来访问。

```js
let a = 1
const b = 2
var c = 3

function add() {
  let a = 4
  var b = 5
  return a + b
}

add()
```

```
GlobalExecutionContext = {
  this Binding: <Global Object>

  LexicalEnvironment: {
    EnvironmentRecord: {
      a: <uninitialized>
      b: <uninitialized>
      add: <function>
    }
    outer: <null>
  }

  VariableEnvironment: {
    EnvironmentRecord: {
      c: undefined
    }
    outer: <null>
  }
}

FunctionExecutionContext = {
  this Binding: <Global Object>

  LexicalEnvironment: {
    EnvironmentRecord: {
      a: <uninitialized>
      Arguments: {}
    }
    outer: <GlobalLexicalEnvironment>
  }

  VariableEnvironment: {
    EnvironmentRecord: {
      b: undefined
    }
    outer: <GlobalLexicalEnvironment>
  }
}
```

当调用`add`时，函数执行上下文就被创建;

在创建阶段，引擎会检查出变量和函数声明，变量被设置为 `undefined`，而函数声明则被完整存储；而`let`和`const`则是未初始化。

#### 执行栈

执行是首先将全局执行上下文压入栈中，遇到函数则创建函数执行上下文并压入栈，引擎执行位于栈顶的上下文，执行完毕则出栈，接着执行下一个上下文。
