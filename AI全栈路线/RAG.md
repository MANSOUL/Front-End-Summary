# RAG

## 实现路径

#### 第一阶段：离线准备（建“索引”）
这一步是把你的文档（PDF/Word/网页）变成AI能快速查找的“目录”，通常在后台异步完成。

1. 文档加载与清洗：读取文档，去除乱码、特殊格式，只留纯文本。

2. 文档切片（Chunking）：把长文切成小块（如500字）。这是最关键的环节，切得太长会引入噪音，太短会丢失上下文。

3. 向量化（Embedding）：调用大厂的Embedding模型（如OpenAI text-embedding-3），把每个文本块转化成浮点数数组（向量），这个数组代表了语义。
  - 开源中文向量模型：推荐使用智源研究院的 BGE 系列（如 bge-large-zh-v1.5、bge-m3）或阿里达摩院的 GTE 系列。
  - 部署工具：可以通过 Ollama 本地部署如 nomic-embed-text 等轻量级向量模型。
  - 商业 API：如果不想本地部署，可以调用 OpenAI 的 text-embedding-3-small 或其他厂商的嵌入 API 来生成向量，再将向量存入向量数据库（如 Milvus、Qdrant、PGVector 等），最后交由 DeepSeek 大模型进行润色与回答

4. 存入向量数据库：将生成的向量存入专门数据库（如 Milvus、Pinecone，或用 Node.js 的 LanceDB），建立索引以便后续检索。


#### 第二阶段：在线检索（问与答）
这是用户提问时的实时流程，你的前端会发起请求，后端处理如下：

1. 问题向量化：把你输入的问题也调用相同接口转成向量。

2. 相似度搜索：在向量数据库里找出和问题向量语义最接近的 Top-K 个文本块（通常用余弦相似度计算）。

3. 构建增强提示词：把检索到的文本块作为“参考资料”，加上你的问题，拼成一个大提示词（例如：基于以下资料：... 请回答：...）。

4. 调用大模型生成答案：把拼好的提示词发给 GPT/Claude，模型基于资料生成最终答案，再用 SSE（打字机效果） 流式返回给前端。
