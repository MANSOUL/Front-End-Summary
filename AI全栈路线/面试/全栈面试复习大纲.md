## 2. 项目：用 JD 的语言讲

### RAG / 商品知识库

**Q：这个系统解决什么问题？你负责哪一段？**

给销售在对话里查产品、报价、拿话术。我做数据模型、检索、Agent 工具约束、SSE 流式和评测门禁。模型只负责理解和组织语言；价格必须来自工具，不能来自记忆。

**Q：表怎么设计的？为什么向量不单独一张表？**

4 张表：产品、价格、话术，向量列直接挂在业务行上。这个业务是 SKU 一对一，不存在长文档切 chunk，命中一行就拿到原文，少一次 JOIN。价格独立成表，改价只更新价格和档位，不重建向量。量到万级、文档变长再拆 embeddings / chunks。

**Q：为什么价格不和产品放一起？**

价格会变，产品描述相对稳。拆开以后改价不触发 embedding。Agent 侧 `search_products` 故意不带价格数字，必须再调 `get_prices`。system prompt 把这条写成红线，评测里工具断言 100% 通过。

**Q：content_hash 干什么？**

上传时对产品文案算 sha256，和库里比。一样就跳过 embedding，省 API 钱；不一样才重算向量。运营反复传同一个 Excel 不会重复花钱。这是数据管道幂等，不是接口幂等。

**Q：检索为什么混合，不纯向量？**

五轮实验，45 条有效集。总体 Recall 0.94 到 0.95，差异不大；话术类 0.94 到 1.00，因为标题是结构化关键词，BM25 比纯语义稳。产品名短、品牌清楚，纯向量也够。选型 ParadeDB：BM25 和向量都在 PostgreSQL 里，过滤条件下推 SQL，不必跨库 JOIN。

**Q：评测怎么当质量门禁？**

50 条分层集：产品、价格、话术、多步、多轮、拒答。看 Recall、Faithfulness、工具断言。工具断言比 Recall 更硬：价格题必须出现 `get_prices`，数字碰巧对但没走工具，改价后就会错。Faithfulness 0.83，低分多半是末尾销售建议被 judge 从严扣，价格编造是 0。

### Agent / 店铺助手

**Q：模型和后端各负责什么？**

顾客对话里选店、填表、确认下单；老板用同一套对话做营销、库存、查询。模型负责理解和提议。建单、删商品、跑 SQL 都由服务端执行，有结构化确认才落地。

**Q：权限怎么隔离？为什么不让模型带 `shop_id`？**

一张 LangGraph，入口按 `role` / `force_intent` 分开。老板 JWT，再校验商店 `owner_id`，通过后把 `shop_id` 写入 graph state，工具一律 `get_shop_id(state)`。模型如果能传 `shop_id`，就等于能改操作对象。请求体换别人的店，归属校验直接 403。

**Q：删除为什么必须人工确认？**

模型只解析「删哪个」。工具第一次返回 `needs_confirmation`，节点 `interrupt()` 把图挂起，HTTP 结束并推确认卡片。真正删除发生在前端 `Command(resume)` 之后，服务端再 `confirm=true` 调工具。写操作和模型提议分开，这就是 HITL。

**Q：Text-to-SQL 哪一步不能信模型？**

不能信生成出来的 SQL，尤其是里面的 `shop_id`。流程：LLM 生成 SQL（temperature 0）→ `validate_and_bind_sql` → 参数绑定执行 → 另一个 LLM 把行说成人话。原 WHERE 必须括起来再 `AND shop_id = :shop_id`，否则 `OR 1=1` 能绕过。禁 UNION / 子查询 / 多语句，先剥注释。执行时 `shop_id` 来自登录态，不来自模型字符串。

**Q：SSE 踩过什么坑？**

限流不用 `BaseHTTPMiddleware`，它会把 SSE 掐断，改纯 ASGI 中间件。LangGraph 最初 `streamMode: "values"` 是节点级输出，看起来不流式，后来改 `"messages"` 才逐 token。Redis 限流计数失败就放行，避免把整个 API 打死。

**Q：下单连点两次会怎样？**

会两单。`create_order` 没有幂等键，前端也没有按请求号查结果。超时后再点就是第二单。信数据库，不信模型说的「下单成功」。改进是确认提交带 client token，创建前查、创建后可查询。现场说到这，别讲成已经防重。

先把这些讲顺：RAG 的表和价格红线；Agent 的权限、HITL、SQL、缺口。数字和框架名放后面。

## 3. TypeScript / Next.js / React

**Q：TypeScript 比 JavaScript 在服务端的价值是什么？**

把接口入参、ORM 行、前端 props 变成同一套形状。错在编译期暴露，比运行到 500 再查日志便宜。不是替测试，是把「字段名写错」这类低级事故提前拦住。

**Q：`interface` 和 `type` 怎么选？`unknown` 和 `any`？**

对象形状用哪个都可以，项目里统一即可。联合、交叉、工具类型用 `type`。`any` 关掉检查；外部输入先当 `unknown`，收窄后再用。API body、`JSON.parse` 的结果都是 `unknown`。

**Q：泛型什么时候才需要？**

同一套逻辑、多种数据类型：响应包装 `ApiResult<T>`、列表组件 `Table<T>`。不要为了写泛型而写。能用具体类型就用具体类型。

**Q：Node 事件循环和浏览器有什么一样、有什么不一样？**

都是单线程执行 JS，IO 交给底层，回调进队列。Node 多了 libuv 线程池（文件、部分加密、DNS），还有 `process.nextTick`、微任务、`setImmediate`。面试够用的一句话：不要在请求路径里做重 CPU；阻塞事件循环，所有连接一起慢。

**Q：什么必须 `'use client'`？**

状态、事件、浏览器 API。没有这些就留在服务器。`'use client'` 是模块边界，这个文件以及它 import 的模块都会进客户端 bundle，不是「这个函数是客户端」。

**Q：RSC 和 SSR 是一回事吗？**

不是。RSC：组件在服务器执行，源码可以不进 bundle。SSR：服务器输出 HTML。App Router 里常一起用：服务器跑 RSC，吐 HTML 做首屏，再带 payload 让客户端接树。payload 只能带能序列化的值，函数和 Class 不能当 props 传给客户端组件。

**Q：为什么调用 `cookies()` 页面就不能静态？**

输出依赖这份请求的 cookie，不能拿构建时那一份给所有人。Full Route Cache 不能收这条路由。鉴权页、购物车、老板后台都是这类。

**Q：四层缓存分别挡什么？**

请求内去重；跨请求的 `fetch` 结果；整页静态成品；浏览器里的客户端导航缓存。生产「页面不更新」多半卡在后三层。`force-dynamic` 只跳过整页缓存。ISR 是给整页成品加寿命，不是给某一句 `fetch` 改名。

**Q：middleware 能替代登录校验吗？**

不能。它能挡住明显未登录的人进页，真数据仍要在 Server Component、Route Handler 或 Server Action 里校验。它跑在 Edge，不适合重逻辑、不适合当权限系统。

**Q：Server Action 安全吗？**

传输有加密 ID，但不是权限系统。必须在 Action 内鉴权、校验入参。适合表单，不适合当对外稳定 API。对外接口用 Route Handler。

**Q：hydration mismatch 常见原因？**

服务器第一帧和浏览器第一帧不一致：`Date.now()`、`Math.random()`、`window` 分支、本地时区格式化。随机值和当前时间放 `useEffect` 之后再写进 DOM。

**Q：React 为什么不能在循环里按条件调 Hook？**

Hook 依赖调用顺序把 state 对上。条件调用一次有一次没有，后面的 Hook 全错位。循环里用组件，条件渲染用组件，不要用 Hook。

**Q：什么会触发重渲染？怎么少渲染？**

state / props / context 变了。父渲染默认子也渲染。拆状态、把不变的子提出去、`memo` 只包真的贵的、列表稳定 `key`（不要用 index 当会插入删除的 key）。先量再优化，不要全局包 `memo`。

**Q：受控和非受控怎么选？**

值由 React state 驱动是受控，适合要即时校验、和别的字段联动。偶尔读一次的原生输入可以用非受控 / `ref`。一个输入不要又受控又自己改 DOM。

## 4. Python / FastAPI

**Q：GIL 是什么？多线程能并行吗？**

同一进程内 Python 字节码同时只跑一个线程。CPU 密集多线程没用，要多进程或原生扩展。IO 密集（HTTP、DB、Redis）多线程或协程仍能提效，因为等 IO 时 GIL 会放。FastAPI 吃的是等待，不是算力。

**Q：协程、线程、进程怎么选？**

网络 / DB 等待 → `async def` + 异步驱动，或同步函数丢线程池。图片、加密、重计算 → 多进程，别放在 `async def` 里死循环。能 SSE 解决的不要上 WebSocket。

**Q：可变默认参数为什么是坑？**

`def f(items=[])` 的 `[]` 在定义时就建好，每次调用复用同一个对象。改成 `items=None`，函数里再 `items = items or []`。面试常手写这题。

**Q：`is` 和 `==`？浅拷贝和深拷贝？**

`==` 比值，`is` 比是不是同一个对象。判空写 `is None`。`x.copy()` / `[:]` 只复制一层；嵌套 dict / list 要 `copy.deepcopy`。

**Q：装饰器是什么？**

函数包函数。`@timer` 等于 `f = timer(f)`。要保住 `__name__` 和文档，里面加 `@functools.wraps(fn)`。FastAPI 的依赖、日志、权限都可以看成这种「先包一层再执行」。

**Q：FastAPI 和 Flask / Django 怎么选？**

Flask 更轻，校验和文档要自己接。Django 带后台、ORM、管理员，偏整站。FastAPI 适合纯接口 + 类型校验 + 自动文档，ASGI 异步顺手。已有 Django 后台不必为了新而拆；新开 API 用 FastAPI。

**Q：Pydantic 和 `response_model` 干什么？**

用 class 描述请求和响应的形状。进来不对自动 422。`response_model` 出口再筛一遍，密码哈希、内部标记不会进 JSON。单靠「return 的时候不写」容易漏。

**Q：Depends 和中间件怎么选？**

全局、不管路由（CORS、日志）用中间件。和某个用户、某个资源有关的用 Depends。鉴权更常是 Depends，因为 `/health` 不该被一刀切。Depends 可以嵌套，同一请求默认只跑一次。

**Q：`def` 和 `async def` 怎么选？**

没有 `await` 用 `def`，框架丢线程池。要等异步库、流式输出，用 `async def`。不要在 `async def` 里 `time.sleep` 或同步大计算。async 吃等待，不是 CPU。

**Q：SSE 和 WebSocket？**

SSE 服务器单向推，打字机、进度够用。WebSocket 双向，聊天室、协同才需要。能 SSE 就别上 WebSocket。Starlette 的 `BaseHTTPMiddleware` 会掐断 SSE，改纯 ASGI 中间件。

**Q：`BackgroundTasks` 能当队列吗？**

不能。它只是响应后在本进程跑一小下，进程没了任务就没了。真排队用 Redis / 专业队列 + worker。我项目里限流和缓存用过 Redis，消息队列生产级没接过，被问到就说到这。

**Q：为什么不在接口里开一个超长事务等模型？**

锁会一直拿着，别人写同一行要排队，还可能超时。外部调用在事务外跑完，最后一条短 `UPDATE`。单条 SQL 自己就是事务；只有多步必须一起成功，才显式开事务。

## 5. MySQL / 索引 / 事务

**Q：MySQL 和 Redis 怎么分工？为什么订单不能只放 Redis？**

订单要重启还在，还要「要么全成功要么全撤销」。Redis 主要在内存，过期、内存满、重启都可能丢最近一秒。详情被刷时把 JSON 缓进 Redis；下单成不成功仍以 MySQL 为准。

**Q：金额为什么用整数？字符集为什么 `utf8mb4`？**

浮点对账会差一分，价格存分，展示除以 100。MySQL 的 `utf8` 最多 3 字节，emoji 存不下，`utf8mb4` 才是完整 Unicode。

**Q：`INNER JOIN` 和 `LEFT JOIN`？**

INNER：两边都配上才留。LEFT：左表全留，右表没有就空着。LEFT 完又在 `WHERE` 里写右表条件，空行会被扔，效果变成 INNER。右表条件写在 `ON` 里。

**Q：深分页为什么慢？**

`LIMIT 20 OFFSET 100000` 要先跳过 10 万行。改成 `WHERE id < 上一页最小id ORDER BY id DESC LIMIT 20`。

**Q：一条 SQL 很慢怎么查？**

`EXPLAIN`。先看 `type` 是不是 `ALL`，`key` 是不是 `NULL`，`rows` 估多少，`Extra` 有没有 `Using index` / `Using filesort`。先治最慢那条，不要给每一列都加索引。

**Q：聚簇索引、回表、覆盖索引？**

主键就是聚簇索引，最底层是整行，按 id 查最快。普通索引最底层是「列值 + 主键 id」，查完往往回表拿整行。覆盖：要的列目录里都有，不用回表，`Extra` 出现 `Using index`。`SELECT *` 很难覆盖。主键要短、要稳。

**Q：最左前缀？建了为什么不走？**

联合索引必须从左边第一列开始用。`(status, created_at)` 可以只查 status，不能只查 created_at。等值列放左，范围列放右。列上套函数、字符串和数字比、`LIKE '%xx'`、`OR` 另一边没索引、区分度太差，都会让索引失效。

**Q：索引是不是越多越好？**

不是。写数据时每本目录都要改。按最慢的 SQL 建，用不上的删。低基数列（性别、是否删除）单独建索引往往没用。

**Q：ACID 在下单里分别指什么？**

原子：订单和库存绑在一起。一致：提交后库存不为负。隔离：别人看不到做到一半。持久：`COMMIT` 之后断电也不丢。日常最容易踩的是隔离。

**Q：默认隔离级别？脏读、不可重复读、幻读？**

InnoDB 默认 REPEATABLE READ。脏读：读到别人没提交的改。不可重复读：同一事务读同一行两次，中间被改了。幻读：同一条件查两次，行数变了。

**Q：快照读和当前读？RR 怎么防幻读？**

普通 `SELECT` 是快照读，看事务开始时的照片，不堵住别人写。`UPDATE` / `FOR UPDATE` 是当前读，要最新值，会锁行。快照读靠 MVCC，当前读靠间隙锁。面试说「InnoDB 的 RR 大多能防幻读」即可，不必先把锁种类背完。

**Q：怎么避免超卖？为什么不能先 SELECT 再在应用里减？**

两个请求都读到 1，都写成 0。闸门放数据库：`UPDATE ... SET stock = stock - 1 WHERE stock >= 1`，看影响行数；或先 `FOR UPDATE`。不要把判断放在 Python 里。

**Q：死锁？事务为什么要短？**

互相等对方的锁形成环。按 id 从小到大锁，事务短，捕获后重试整笔。生成详情、调模型都在事务外，最后一条 UPDATE 即可。

**Q：`WHERE` 没走索引，锁一行会怎样？**

数据库不知道锁谁，可能锁一大片。条件必须能用上主键或唯一索引。和 Agent 里「删除必须精确到商品 id」是同一类问题。

## 6. Redis

**Q：没有 Redis 也能跑，为什么还要它？**

访问量不大时不需要。它扛的是 MySQL 不该反复扛的事：详情被狂刷、多进程共享验证码和限流、两台机器不要同时做同一件贵操作。判断：丢了能不能从 MySQL 再造？能，才放 Redis。

**Q：旁路缓存怎么写？为什么删缓存不是改缓存？**

读：先 Redis，没有再 MySQL，再写回 Redis。写：先成功写 MySQL，再删 Redis。改缓存容易出现「库失败了缓存却是新的」，或并发把旧值写回去。删掉后下一次读会重建。

**Q：穿透、击穿、雪崩？**

- 穿透：查根本不存在的 id，每次打到库。空结果也缓存很短，挡住乱 id。
- 击穿：一个热点刚好过期，大家一起回源。重建时加短锁，只让一个打库。
- 雪崩：大批 key 同一秒过期。过期时间加随机抖动。

**Q：为什么计数要用 `INCR`？**

GET 再 SET 不是原子的，两个请求都读到 7，都写成 8。限流、错误次数用 `INCR`。库存最终仍以 MySQL 为准。我项目里 IP 限流就是计数；Redis 挂了选择放行，避免把 API 打死。

**Q：分布式锁为什么不能直接 `DEL`？**

`SET lock {随机串} NX EX`。解锁前确认还是自己的随机串再删。直接 `DEL` 可能删掉别人已经抢到的锁。我业务里还没用到这把锁，超卖靠 SQL，不靠 Redis 锁。

**Q：Redis 单线程为什么快？能当数据库吗？**

命令执行单线程，数据在内存，没有解析 SQL + 翻磁盘那套成本。持久化只是保险，仍可能丢最近一秒，订单真相不能只放 Redis。

**Q：五种结构各举一个业务例子。**

String：详情 JSON、验证码、锁、限流。Hash：商品多个字段。List：轻量队列。Set：去重。ZSet：排行榜。先会 String 和限流，其他被问到对上业务即可。

## 7. Docker / Linux

**Q：镜像、容器、卷有什么区别？**

镜像是模板。容器是跑起来的进程，删了里面没放卷的文件就没了。卷在容器外面，MySQL 数据必须放卷上。`compose down` 停容器、卷还在；`down -v` 连卷一起删。

**Q：Docker 和虚拟机？**

虚拟机带完整操作系统，重。容器共用主机内核，只打包进程和依赖。适合把 FastAPI + MySQL + Redis 整包带走，不适合当另一个 Windows。

**Q：Compose 里为什么不能写 `localhost:3306`？**

每个容器有自己的 localhost。api 容器里的 localhost 是它自己，不是旁边的 MySQL。同一网络用服务名 `db`、`redis`。只有在电脑上连映射端口时才用 `127.0.0.1`。

**Q：`depends_on` 为什么不够？**

它只保证先启动，不保证 MySQL 已经能接连接。接口起太快就会连不上。db 加 healthcheck，api 等到健康再起。

**Q：为什么听 `0.0.0.0`？**

听 `127.0.0.1` 时容器外面进不来。`0.0.0.0` 才对外网卡开放。`8000:8000` 是「电脑的 8000 转到容器的 8000」。容器之间走内部网络，不必每个服务都映射到主机。

**Q：镜像为什么又大又慢？**

没忽略 `.git` / 虚拟环境；或每次改代码都重装依赖。先复制依赖清单再复制源码，利用层缓存。密钥不要写进 Dockerfile，走环境变量。

**Q：虚拟环境和 Docker 是什么关系？**

虚拟环境：同一台机器上多个项目的包互不污染。Docker：整个运行环境打包，是虚拟环境的超集。容器里可以再来一层 venv，很多镜像直接装到系统 site-packages。

**Q：K8s 用过吗？**

生产是 Docker Compose。K8s 知道 Pod / Service / Deployment 的分工，没有在集群里发过版。如果团队已经在用，我可以从 Dockerfile 和健康检查往上接。

Linux 够用的几句：进程、端口、日志用 `docker logs` / `journalctl`；磁盘和内存先看谁把机器打满；配置和密钥不进镜像。

## 8. 工程化、测试、稳定性

**Q：你怎么保证改了检索或接口不把线上打坏？**

RAG 侧有 50 条分层评测，改 top-N、改写开关都要跑一遍，大约 10 分钟。接口侧 FastAPI 可以用 TestClient，不真起端口。关键路径：鉴权失败要 401/403，价格必须走工具，SQL 校验要拦住注释和多语句。没有的部分照实说：还没有完整 CI 质量门禁，本地脚本和评测集是现在的门。

**Q：Code Review 你看什么？**

权限有没有绕过（`shop_id` 是不是来自登录态）、有没有超长事务、有没有把密钥写进代码、错误是不是返回了正确状态码、测试有没有覆盖失败路径。格式和命名次之。我推规范靠评审意见和示例 PR，不是靠口号。

**Q：线上接口变慢，你怎么查？**

先看是所有接口慢还是一条 SQL / 一个外部调用慢。DB：`EXPLAIN`、慢查询日志。应用：是不是在 `async def` 里阻塞，连接池是不是满了。缓存：是不是集体失效打到库。我现在主要靠日志和耗时打点，没有 Prometheus / Grafana，这是缺口。

**Q：可观测性你怎么理解？**

至少三件事能回答「谁在什么时候对哪个资源做了什么」：结构化日志、请求 id 贯穿、关键业务指标（延迟、错误率、工具调用次数、模型花费）。再往上才是指标系统和 tracing。我项目里 SQL 打 `internal` 不进 SSE，避免把内部语句漏到用户侧，也是观测和安全的一部分。

**Q：CI/CD 你怎么看？**

最小可用：lint + 单测 + 构建镜像，主分支才能发。质量门禁先卡测试和类型，再卡覆盖率数字。我做过 Docker 化本地一键起，完整流水线如果团队还没有，可以从「合并前必须绿」做起，不一次上大平台。

**Q：ORM 怎么选？会不会手写 SQL？**

CRUD、事务边界用 ORM 不容易拼错。复杂报表、故意走覆盖索引、Text-to-SQL 校验后的只读查询，手写 SQL 更清楚。ORM 不是不能碰 SQL，是默认路径更安全。

## 9. 系统设计（内部平台口径）

现场画：客户端 → API → 服务 → DB / Redis。补三条失败路径：鉴权失败、下游超时、重复提交。

**Q：设计一个内部下单接口。**

1. 鉴权：老板 JWT + 商店归属；顾客会话只写自己的草稿。
2. 数据：订单表是真相；库存用一条条件 UPDATE 扣减；价格当时快照进订单行，不读实时价。
3. 幂等：客户端带 `Idempotency-Key`，服务端按 key 建唯一约束，重复提交返回同一单。我现在这层没做，会当成风险讲。
4. 超时：请求内同步 commit。超时后前端用 key 查询，不凭模型话术重试创建。
5. 缓存：商品详情可缓存；下单结果不以 Redis 为准。

**Q：设计权限。**

身份（谁）和授权（能碰哪家店、哪类操作）分开。写操作按资源 id 校验归属，不信请求体里的 `shop_id`。只读查询即使走 LLM 生成 SQL，执行时仍注入登录态的 `shop_id`。公开试用 `force_intent`，进不了库存和查数。

**Q：流式接口怎么做才稳？**

后端 `ReadableStream` / SSE；代理和中间件不能缓冲整包。取消请求要能停模型调用。心跳防止网关超时。内部 thinking / SQL 过滤后再推给前端。Redis 限流失败放行，优先保可用。

**Q：如果流量涨 10 倍，你先动哪？**

先看瓶颈：DB CPU、单条慢 SQL、模型调用、还是 Node/Python 进程打满。读多写少加缓存；写路径先保证幂等和短事务；模型调用限流、排队，不要在请求里并行打爆。没到万级 SKU 之前不先上独立向量库。

## 10. 前端保底层（只到这个深度）

这份岗很少靠 CSS 边角分胜负。下面这组卡住能捡起来即可。

**Q：事件循环：微任务和宏任务？**

同步代码跑完，先清空微任务（`Promise.then`、`queueMicrotask`），再取一个宏任务（`setTimeout`、IO 回调）。`async/await` 在 await 之后的部分进微任务。不要用这个解释所有卡顿，卡顿更常见是长任务和强制布局。

**Q：闭包？**

函数记住定义时的词法环境。React 里过期闭包：事件处理函数抓住了旧 state。解法是函数式更新 `setS(s => s+1)`，或把值放 ref。

**Q：`this` / 箭头函数？**

普通函数的 `this` 看谁调用；箭头函数没有自己的 `this`，向外找。React class 里回调要绑，hooks 组件用箭头或函数声明即可，不要在 hooks 里玩 `this`。

**Q：跨域是前端的事还是后端的事？**

浏览器拦的，放行名单写在后端。FastAPI 加 CORS 中间件。服务器之间 HTTP（Next Route Handler 打 FastAPI）没有 CORS。带 cookie 时不能 `*`，要明确 origin 且 `credentials`。

**Q：XSS / CSRF 你怎么防？**

XSS：不把用户输入当 HTML 插，React 默认转义，`dangerouslySetInnerHTML` 当红线。CSRF：cookie 会话要 SameSite，改数据接口校验 CSRF token 或改用 Authorization header。我项目里老板接口走 JWT header，不靠跨站 cookie 做写操作。

Vue 源码、Webpack 细节、微前端、小程序、RN：主动不展开。被问到就说近几年主战场是 React / Next。

## 11. 缺口题，背的是诚实而不是补丁

**Q：K8s / Prometheus / Grafana？**

没有在生产搭过。现在是 Docker Compose + 日志。下一步会先加请求 id 和延迟直方图，再接到现成的指标系统。

**Q：消息队列？**

`BackgroundTasks` 不是队列。异步投递、削峰、重试我知道该用 Redis Streams 或专业 MQ，项目里还没接。当前写路径是请求内同步 commit。

**Q：企业 ERP / OA 集成？**

没有对接过金蝶 / 钉钉这类系统。我做过的是内部业务 API、鉴权和数据隔离。集成无非是：对方的鉴权、幂等、对账、失败重试，这些原则我在自己的下单和 SQL 校验里用过。

**Q：带过团队吗？**

没有正式 TL 职级。做过方案写清楚、评审里挡权限和事务问题、把约定写成文档让别人能接着改。指导中初级我能做的是把隐性经验写成可复制的检查项，而不是管人。

**Q：高可用怎么做的？**

单实例 + Compose，没有多活和自动故障转移。可用性上我做的是失败降级：限流挂了放行、模型超时给可读错误、写操作人工确认。真正的多副本和健康检查切流，要上编排之后才有。

## 13. 临场顺序

1. 开场按第 1 节，90 秒停。
2. 项目先讲决策和缺口，再讲模型和框架名。
3. 原理题用第 3 到第 7 节的 4 句结构，不要展开成课堂。
4. 不会的先复述题目，再划边界，再给下一步。不要沉默，也不要编 K8s。
5. 手写优先：旁路缓存伪代码、超卖 SQL、FastAPI 一个带 Depends 的接口、SSE 为什么不用 BaseHTTPMiddleware。

开口标准：每题 90 秒能讲完，还能扛住两轮「为什么」和一轮「如果失败了怎么办」。
