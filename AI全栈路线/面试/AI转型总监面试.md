# 1. 自我介绍

**Q：先做个自我介绍。**

我是前端出身。早年在长沙做过安卓，后来到深圳一直做 Web。在云集做过小程序和交易链路，也做过独立于主站的业务。近一年后端写得多了，开始做 AI 应用。

最近就两件事。一个是给内部销售用的知识库，对话里查产品、报价、拿话术。一个是探索Ai在线下小商店应用场景下，给小店老板用的经营助手，一条对话处理营销、库存、查数，顾客也能在对话里下单。模型负责听懂和提议，改库存、下单、报价格，都是服务端执行。

ERP、钉钉我没接过，企业级 Agent 平台也没做过。我比较熟的是把一个具体场景做成能上线、能拦住乱操作的东西。

# 3. 销售知识库

**Q：这个系统解决什么问题？你负责哪一段？**

给内部销售用，老板们的主业是酒类经销。以前查一款酒，要翻资料、问同事、再对价格。我做成对话：问产品、问话术、问价格。我负责整体设计开发，包括数据模型、检索、工具约束、流式输出和评测都是我做的。模型只负责理解和组织语言，价格必须来自接口。

**Q：价格为什么不能让模型报？**

业务上价格变动相对频繁，模型记的可能是旧的。搜产品时故意不带价格数字，必须再调取价接口。评测里价格题必须真正出现取价，50 道工具断言都过了。数字碰巧对、但没走接口，也算失败，因为改价后就会错。

**Q：话术怎么进知识库？**

话术要人确认过才参与检索。没确认的不进。避免过期口径和随口话术被搜出来。

**Q：为什么混合检索，不纯向量？**

产品名短，品牌清楚，纯向量其实够用。话术标题是结构化关键词，比如「太贵怎么接」，关键词检索更稳。五轮实验，45 条有效集，话术召回从 0.94 到 1.00，整体从 0.95 到 0.98。

**Q：表怎么设计的？为什么不切片？**

四张表：产品、价格、话术，向量挂在业务行上。这个业务是一款酒一行，命中一行就拿到原文。价格单独放，改价不重建向量。量到万级、文档变长再切。

**Q：检索不到怎么办？答错怎么办？**

检索不到就拒，不拿通用知识补。评测里专门有拒答题。答错看是检索错还是模型编。价格编造是 0；忠实度低，多半是末尾销售建议被判严，不是乱报价。

**Q：权限怎么做？销售能不能看到底价？**

这套是内部销售知识库，按内部账号用。底价、采购价我没做单独隔离。企业里如果销售不能看采购底价，检索前就要按角色过滤，不能先搜出来再靠模型嘴上瞒。

**Q：评测怎么当质量门禁？**

50 条分层题：产品、价格、话术、多步、多轮、拒答。看召回、忠实度、工具断言。工具断言比召回硬：价格题必须走取价。没过评测，不拿去改线上。

# 4. 门店经营助手

**Q：这个助手帮谁完成什么？**

老板用一条对话处理营销、库存、查询。顾客在对话里选店、填表、确认下单。模型负责听懂和提议。建单、删商品、跑 SQL，都是服务端执行，有结构化确认才落地。已经上线。

**Q：为什么不是聊天机器人？**

聊天机器人只回答。这套会改数据：下单、删商品、查本店库存。所以写操作和模型提议是分开的。模型可以说「要删这个」，真正删除发生在人点确认之后。

**Q：删除为什么必须人确认？**

不只是删除，基本涉及到改事实的操作都会有人工确认。模型只解析删哪个。流程先停住，前端弹出确认。人点确认，服务端才删。人改口发新消息，未完成的确认丢掉，不当删除。防止对话里误删。

**Q：查数为什么不信模型写的 SQL？**

模型生成 SQL，服务端再校验。只能查、只能查商品表，注释剥掉，禁止多语句、UNION、子查询。原来的条件括起来，再强制带上当前店铺。店铺 ID 从登录态注入，不让模型填。不然 OR 1=1 就能把别的店查出来。

**Q：权限怎么隔离？试用会不会走进库存？**

一张流程，三个入口。老板要登录，校验是不是自己的店。顾客免登录，只进客服。公开试用锁死营销，不能进库存和查数。商品、订单都按店铺过滤。请求体换成别人的店，直接拒绝。

**Q：顾客下单怎么走？**

选店、填表、确认建单。卡片当轮用完就清。选了哪家、买什么跨轮记着。确认时如果商品和地址都齐，跳过意图分类，服务端直接建单。模型只说人话，不再抽地址电话。

**Q：连点两次确认会怎样？**

会两单。现在创建没有防重，超时后再点就是第二单。信数据库，不信模型说的下单成功。改进是确认时带请求号，创建前先查。

**Q：上线了为什么没用户？**

产品假设没跑通。我们都是假设店主愿意为营销文案、库存管理、连接C端用户的便利付费，客户愿意为了省时便利去看社区周边小店，公开试用后没做出用户，就停了。工程判断我还认：写操作要人确认，查数要锁店铺，模型不能直接改数据。如果重做，会更早验证有没有人愿意用，不会先铺六路能力。

**Q：六路 Agent 是怎么拆的？**

老板侧：营销、库存、查询、店铺管理、订单。顾客侧固定客服。上面只有一个路由，不算业务。公开试用不走分类，直接营销。对不上就兜底，不让它随便进写操作。

# 5. 现场丢一个你没做过的场景

统一先答这四句，再展开。不要一上来上多 Agent。

1. 这是查资料，还是要改系统？
2. 只读工具有哪些，写工具为什么只有一个？
3. 哪步问人，哪步系统拒，哪步才审批？
4. 身份和权限从登录态取，不准就拒，不让用户口头报。

**Q：如果让你做采购跟单助手？**

先问现在跟单卡在哪：延迟、缺货，还是对账。查物流、查库存是只读，可以先做。改采购单、对供应商催货是写入，必须人确认。供应商主数据和订单状态我没接过 ERP，真做要先有只读接口。90 天我不会先选这个，数据和写回都重。

**Q：客服质检助手怎么做？**

质检是对照规则打分，不是开放聊天。规则能写成条的，先规则；语气、承诺、态度再用模型。结果要能指出哪一句违规，人抽检查。误杀高就收紧，不要直接拿去考核。质检本身是只读，不改工单。

**Q：会议任务助手？**

纪要是生成，可以先做。建任务、派人、写日历是写入。会议纪要不能当事实源，任务要人确认后再建。谁能看到哪场会，按会议权限走，不能全员可搜。

**Q：经营分析助手？**

我做过类似的：自然语言查本店数。关键是数必须来自查询，不能来自模型记忆。数对不上就说查不到，不许编。先做固定问题，比如今天销了多少、什么滞销；不要一上来做开放归因。

**Q：90 天第一个数字员工你选哪个？**

选销售知识库，或者经营查询。痛、频、标准、数据够，写操作能做人审。不选采购跟单，不选先搭平台。先做一个场景跑起来，再把鉴权、评测、人审抽成可复用的。

**Q：Agent、工作流、RPA 怎么选？什么时候不该上 Agent？**

步骤固定、规则清楚，用工作流。只是点已有系统、没接口，才考虑 RPA。要理解自然语言、路径不固定，才上 Agent。不该上的情况：必须改钱、改库存、对外部发消息，又没有人审。那种先做成表单加审批。

# 6. 总监视角

**Q：业务说先做个 ChatGPT 出来，你怎么接？**

先问替掉谁的哪一步，数据从哪来，写回哪里，错了谁负责。先做一个高频场景。查资料可以先上；改业务数据必须人审。不会一上来做全公司都能问的万能助手。

**Q：准确率只有 80%，能不能上线？**

看动作。查资料、起草可以上，标不确定，人可以改。改库存、改订单、对供应商发消息，80% 不能直接上，必须人审。上线看人工接管率和差错率，不看模型分数。

**Q：模型和流程，企业 AI 到底改的是哪一个？**

先改流程。模型只是其中一步。哪个节点用规则、哪个用模型、哪个必须人审，这是设计。只换模型、流程不动，最后还是聊天窗口。

**Q：AI 项目失败最常见的原因？**

场景选大了，数据不干净，写操作没有人审，上线没有指标。我自己的门店助手就是例子：工程能跑，付费假设没验证，就停了。

**Q：LangGraph、Dify、Coze 你怎么看？什么自己写？**

验证想法可以用 Dify、Coze。要上线、要鉴权、要人审、要写回业务系统，我倾向自己用 LangGraph 加服务端。门店这套删除确认、SQL 校验、店铺隔离，放到现成编排里不好控。不是框架更高级，是责任在服务端。

**Q：10 个数字员工同时跑，你怎么做平台？**

我没做过企业级平台。最小该有的是：统一登录和权限、Prompt 和 Agent 版本、调用日志、费用、人工接管入口。先让两个助手共用鉴权和日志，再抽平台。不会先做管理后台再找场景。

# 7. 缺口，主动说

**Q：ERP / 钉钉 / BI 接过吗？**

没有，生产没接过。概念知道。真要接，先只读。模型输出要写回 ERP，必须审批和防重，不会让模型直接打接口。

**Q：小程序会吗？**

会。云集做过小程序和交易链路。门店助手也有 Taro 小程序端，和 Web 共用一套交互。

**Q：Vue 熟不熟？**

做过 Vue 和 uni-app。最近主栈是 React / Next.js。管理后台我能做，源码级细节不是我现在的主场。

**Q：K8s、消息队列、监控？**

生产用过 Docker Compose。K8s 只了解概念。监控现在是日志加链路，没搭过 Grafana。消息队列生产没接过。

**Q：多租户、制度知识库、供应商知识库做过吗？**

店铺隔离做过，按登录态锁店铺。制度、供应商这类长文档知识库没做过企业级。销售那套是一款酒一行，不是制度切片。如果做制度，要处理版本、过期和口径冲突，检索不到就拒。
